# 티츄 규칙 명세 (Rules Spec)

규칙 엔진 구현자를 위한 정밀 명세. 조합 판정·파워 계산·봉황/마작/개/용/폭탄의 세부 규칙·라운드 정산까지
"바로 코드로 옮길 수 있는" 수준으로 기술한다.

## 0. 참고 자료

- **jstanley0/tichu** (Ruby, `master`) — 서버가 매 턴 합법수 전체를 enumerate하여 클라이언트에 내려주는 구조라
  규칙이 코드에 가장 명시적으로 드러난다. 인용 시 `jstanley0:<path>#L<line>` 형식으로 표기.
  - `tichu/card.rb`, `tichu/deck.rb`, `tichu/play.rb`, `tichu/state.rb`, `tichu/player.rb`
  - `spec/play_spec.rb`, `spec/card_spec.rb` (봉황 엣지케이스가 테스트로 명문화됨 — 신뢰도 최상)
- **pspanoudakis/tichu-js** (TypeScript, `master`) — 사람이 카드를 직접 선택하고 클라이언트가 그 선택의 합법성만
  검증하는 구조라, 봉황 대체값처럼 jstanley0가 "자동 강제"하는 지점에서 오히려 "플레이어 자유 선택"을 허용하는
  경우가 있어 교차검증에 유용하다. 인용 시 `tichu-js:<path>#L<line>` 형식으로 표기.
  - `src/CardInfo.ts`, `src/Deck.ts`, `src/CardCombinations.ts`, `src/GameLogic.ts`
- 공식 룰 요약(교차검증용, WebSearch): officialgamerules.org, ultraboardgames.com

두 구현의 카드 값 스케일은 서로 다르고(예: jstanley0는 Dragon=18, PHOENIX=16 내부 랭크; tichu-js는 Dragon=20,
Phoenix=0.5), **이 프로젝트가 채택한 인코딩·파워 스케일과도 다르다.** 아래 문서는 전부 **이 프로젝트의 인코딩**
기준으로 재서술했다.

## 1. 카드 인코딩과 파워

### 1.1 카드 (smallint 0..55, 총 56장)

| 범위 | 의미 |
|---|---|
| `c < 52` | `suit = floor(c/13)` (0=옥/초록, 1=검/검정, 2=탑/파랑, 3=별/빨강), `rank = c%13 + 2` (2..14, 14=A) — 4수트 × 13랭크 = 52장 |
| `c = 52` | 마작(Mahjong). 조합 판정상 `rank = 1` |
| `c = 53` | 개(Dog) |
| `c = 54` | 봉황(Phoenix) |
| `c = 55` | 용(Dragon) |

카드점수(트릭/손패 정산용, 합계 100): 5=5점, 10=10점, K=10점, 용=+25점, 봉황=-25점, 나머지(2,3,4,6,7,8,9,J,Q,A,
마작,개)=0점. (jstanley0:tichu/card.rb#L186-192, tichu-js:src/GameLogic.ts#L836-860, officialgamerules.org)

### 1.2 조합 파워 (정수, 높을수록 강함)

| 조합 | power 계산식 |
|---|---|
| 싱글(일반 카드) | `rank * 2` (마작 포함, 마작은 rank=1 → power=2) |
| 싱글(봉황, 리드) | `3` (= 마작 power 2 + 1) |
| 싱글(봉황, 이전 싱글 power P 위에 낼 때) | `P + 1` (홀수). **단, P=40(용)일 때는 낼 수 없음 — 예외 규칙, 아래 §3 참조** |
| 싱글(용) | `40` (고정값. `18*2=36`이 아니라 별도 상수) |
| 페어 / 트리플 / 풀하우스 | `rank * 2` (봉황이 대체값으로 들어가도 **+1 없음** — 싱글과 다름, 흔한 실수 지점) |
| 스트레이트(연속 5장 이상) / 연속 페어(사다리) | `top_rank * 2` (top = 조합 내 최고 랭크) |
| 폭탄(4장 조합) | `100 + rank` (rank 2..14 → 102..114) |
| 폭탄(스트레이트 플러시, 같은 수트 5장 이상) | `1000*len + rank` (len=조합 길이 5..14, rank=최고 랭크 2..14 → 5002..14014) |

`1000*len` 스케일 덕분에 "더 긴 스트레이트플러시는 항상 더 짧은 것보다, 그리고 항상 4장 폭탄보다 강하다"가
숫자 비교 한 번으로 성립한다. 개(Dog)는 파워가 없다 — 아래 §5 참조.

## 2. 조합 8종 판정 조건

공통 규칙: 새로운 수는 (a) 폭탄이거나, (b) **직전 트릭과 조합 타입이 동일**하고(스트레이트/연속페어는 **길이도
동일**해야 함) power가 **엄격히 더 커야** 한다. 트릭이 비어 있으면(리딩) 아래 8종 및 개(Dog) 중 아무거나 낼 수
있다(단 §4의 소원 의무가 걸려 있으면 제한됨).

1. **싱글(Single)** — 카드 1장. power=§1.2. 봉황 단독 플레이는 §3.
2. **페어(Pair)** — 같은 랭크 2장, 또는 실물 카드 1장 + 봉황(그 랭크로 대체). power=`rank*2`.
3. **트리플(Triple)** — 같은 랭크 3장(봉황 1장까지 대체 가능). power=`rank*2`.
4. **스트레이트(Straight, ≥5장)** — 서로 다른 랭크가 연속(간격 없이) 5장 이상, 랭크당 1장씩. 마작(rank=1)은
   `1-2-3-4-5`의 최하단으로 참여 가능. 봉황은 **rank 2..14로만** 대체 가능(마작 자리=rank1은 대체 불가, 마작
   실물 카드가 있어야만 rank1이 스트레이트에 들어감). **같은 수트로만 구성된 5장 이상 연속은 스트레이트가 아니라
   자동으로 폭탄(스트레이트 플러시)으로 취급한다** — 일반 스트레이트로는 낼 수 없음
   (jstanley0:tichu/play.rb#L191, `next if cards.map(&:suit).uniq.size==1`). power=`top_rank*2`, 이어내기 시
   길이가 이전과 반드시 같아야 함. 봉황 배치 규칙은 §3.3.
5. **연속 페어(Ladder/Steps, ≥2쌍)** — 연속된 랭크의 페어가 2쌍 이상(길이=2×쌍수, 최소 4장). 봉황은 그 중 정확히
   한 쌍의 짝을 맞추는 데만 쓸 수 있다(봉황 1장뿐이므로). power=`top_pair_rank*2`, 이어내기 시 길이 동일해야 함.
   봉황 배치의 상/하단 우선순위는 **미확정**(§9 참조).
6. **풀하우스(Full House)** — 트리플 + 페어(랭크는 서로 달라야 함), 총 5장. 봉황은 트리플 쪽이든 페어 쪽이든
   대체 가능. power=`triple_rank*2`. 봉황 배치 규칙은 §3.4.
7. **폭탄 — 4장(Bomb, 4-of-a-kind)** — 같은 랭크 4장(수트 무관). **봉황 대체 불가**(어떤 폭탄에도 봉황 사용
   불가 — §3.1). power=`100+rank`.
8. **폭탄 — 스트레이트 플러시(Bomb, Straight Flush)** — 같은 수트로 연속 5장 이상. 마작/봉황/용/개 등 특수카드는
   **어떤 특수카드도 참여 불가**(수트가 0(무색)이라 애초에 1~4수트 조합에 섞일 수 없음). power=`1000*len+rank`.

폭탄은 위 (a) 규칙대로 조합 타입 불문 어떤 트릭 위에도(단, 상대가 이미 폭탄을 냈다면 그보다 강한 폭탄만) 낼 수
있다. 자세한 사용 규칙은 §7.

## 3. 봉황(Phoenix) 규칙 전체

### 3.1 와일드카드로서의 봉황
- 페어/트리플/풀하우스/스트레이트/연속페어에서 실물 카드 1장의 랭크를 대신하는 와일드카드로 쓸 수 있다.
  대체 가능 랭크는 2..14뿐이며, 마작(rank=1) 자리는 대체할 수 없다(jstanley0:tichu/card.rb#L158-160
  `substitute!`).
- **폭탄(4장/스트레이트플러시) 어디에도 참여할 수 없다.** jstanley0의 `Bomb.enumerate`는 봉황 대체를 아예 시도하지
  않고(jstanley0:tichu/play.rb#L259-273), tichu-js의 `Bomb.createBomb`도 특수카드가 섞이면 즉시 무효 처리한다
  (tichu-js:src/CardCombinations.ts#L621-646).

### 3.2 싱글로 낼 때
- **리드(선)로 낼 때**: power=3 (= "1.5"의 정수화, 마작 power 2 + 1).
- **이전 싱글 위에 얹을 때(이전 power=P)**: power=`P+1`(홀수). 즉 이전 카드보다 정확히 0.5랭크 위.
- **용 위에는 절대 낼 수 없다.** P=40(용)일 때 `P+1=41`처럼 보이지만 이는 규칙상 명시적 예외로 금지된다
  (jstanley0:tichu/play.rb#L121 `if prev_play && prev_play.rank < Card::DRAGON`;
  tichu-js:src/GameLogic.ts#L332-336 "The Phoenix cannot be played on top of the Dragon").
- **따름 규칙(A 위)**: A(power=28)에 봉황을 얹으면 power=29가 되고, 이는 실물 카드로 만들 수 있는 최댓값보다
  크므로 이 이후로는 **용(40) 또는 폭탄만** 이길 수 있다 — 별도 규칙이 아니라 위 두 조항의 자연스러운 결과다.
  (jstanley0:spec/play_spec.rb#L22-23으로 "봉황이 A를 이길 수 있고, 용은 못 이긴다"가 테스트로 확정됨)

### 3.3 스트레이트에서의 봉황 배치
- 봉황은 스트레이트 내 빈 랭크 하나를 채운다. **배치는 결과 스트레이트의 top이 최대가 되는 쪽으로 강제된다**:
  실물 카드의 최댓값이 이미 A(14)가 아닌 한, 봉황은 항상 "한 칸 위로 확장"하는 용도로만 유효하며, 그보다 낮은
  하단-채움 결과는 무효(선택지에서 배제)된다. 실물 카드 최댓값이 이미 A라서 위로 확장이 불가능할 때만 봉황이
  아래쪽 빈 자리를 채우는 것이 허용된다.
  - 근거: jstanley0:tichu/play.rb#L192 `next if cards[0].substituted_phoenix? && rank < Card::ACE` — 봉황이
    구간의 최하단 카드로 쓰였는데 결과 top이 A 미만이면 그 조합 자체를 합법수 목록에서 제거한다.
  - 테스트로 확정: `4,5,6,7,+봉황` → 오직 top=8(상단 확장)만 유효(jstanley0:spec/play_spec.rb#L45).
    `J,Q,K,A,+봉황` → 위로 확장 불가(A가 이미 최댓값)하므로 봉황이 10 역할을 하는 하단-채움만 유효,
    top=A(jstanley0:spec/play_spec.rb#L46).
  - **주의**: 이 강제는 jstanley0의 채택 방식이며, tichu-js는 반대로 플레이어가 봉황의 대체값을
    자유롭게 선택하게 한다(`PhoenixCard.tempValue`를 UI에서 직접 지정, tichu-js:src/CardCombinations.ts#L430-449
    `Kenta.create`). 이 프로젝트는 과제 지시에 따라 **jstanley0 방식(상단 우선 강제)**을 채택한다.

### 3.4 풀하우스에서의 봉황 배치
- 손에 자연 트리플이 있으면 봉황은 그냥 페어 쪽 와일드카드로 자유롭게 쓰인다(모호함 없음).
- **모호한 경우는 오직 "실물 페어 2개 + 봉황"뿐**: 이때 봉황은 반드시 **더 높은 랭크의 페어를 트리플로
  완성**하는 데 사용해야 하며, 낮은 쪽을 트리플로 만드는 조합은 애초에 합법수가 아니다(플레이어가 선택할 수
  없음). 예: `5,5,6,6,+봉황`이면 반드시 트리플=6, 페어=5인 풀하우스(power=12)만 가능, 트리플=5 버전은 무효.
  - 근거: jstanley0:tichu/play.rb#L244-246 `if combo[0].any?(&:substituted_phoenix?); next if rank <
    combo[1][0].rank` — 트리플 쪽에 봉황이 들어갔는데 그 랭크가 페어 쪽보다 낮으면 제거.
  - 테스트로 확정: `5,5,6,6,+봉황` → 합법수 정확히 1개(더 높은 쪽)뿐(jstanley0:spec/play_spec.rb#L59,
    "# higher only"). 원 README의 유명한 예시("5,5,9,9,P → 9로 해석")도 이 규칙의 사례다.
  - **주의**: tichu-js는 여기서도 플레이어 자유 선택(`PhoenixCard.tempName`을 직접 지정,
    tichu-js:src/CardCombinations.ts#L475-503 `FullHouse.create`)을 허용한다. 과제 지시에 따라 이 프로젝트는
    jstanley0 방식(높은 쪽 강제)을 채택한다.

## 4. 마작(Mahjong)과 소원(Wish)

### 4.1 마작 카드 자체
- rank=1, power=2. 싱글로는 항상 power가 가장 낮은 축에 속하므로(개 제외) **리드로만** 낼 수 있고, 이미 깔린
  싱글 위에 얹어 이길 수는 없다.
- 스트레이트의 최하단(`1-2-3-4-5`)으로 참여 가능. 이때는 리드뿐 아니라 이전 스트레이트를 이기며 낼 때도
  포함될 수 있다(스트레이트 비교는 top 기준이므로 마작이 맨 아래 있어도 무방).

### 4.2 소원 설정
- 마작이 포함된 **모든 합법수**(싱글 리드든, `1-2-3-4-5` 스트레이트로 이전 스트레이트를 이기는 수든)를 낼 때,
  그 플레이어는 랭크 2..14 중 하나를 "소원"으로 지정할 수 있다(jstanley0:tichu/state.rb#L277-281).
- 라운드당 마작은 1장뿐이므로 소원도 라운드당 최대 1회 설정된다.

### 4.3 소원 충족
- 이후 **어느 플레이어의 어떤 합법수든**, 그 안에 소원 랭크의 **실물(수트 있는) 카드가 1장이라도 포함되면**
  즉시 충족되어 소원이 해제된다. 그 카드가 조합의 "결정 랭크"(예: 스트레이트의 top)일 필요는 없다 — 예를 들어
  `5-6-7-8-9` 스트레이트는 소원=6이어도 충족시킨다(jstanley0:tichu/play.rb#L72-75 `fulfills_wish?`,
  `cards.any? { card.normal? && card.rank == wish_rank }`).
- **봉황이 그 랭크로 대체되어 있어도 충족되지 않는다** — `card.normal?`은 수트가 실제 1~4인 카드만 인정한다
  (봉황의 수트는 항상 0). 공식 룰 요약도 "봉황은 소원 충족 카드로 언급되지 않는다"고 확인.
- 우연히도(고의든 아니든) 소원 랭크를 포함한 폭탄을 내면 그것도 충족으로 카운트된다(fulfills_wish? 체크에
  플레이 타입 제한이 없음).

### 4.4 소원 의무
- 소원이 걸려 있는 동안 **모든 플레이어의 매 차례**(리드든 이어내기든)에 대해: 그 플레이어가 소원 랭크의 실물
  카드를 갖고 있고, 그 카드를 포함해 **지금 당장 낼 수 있는 합법수**(이어내기라면 타입/길이가 맞고 직전 트릭을
  실제로 이기는 수, 리드라면 아무 조합이든)를 만들 수 있다면 → 그 턴의 합법수는 "소원을 충족시키는 수들"과
  "폭탄"으로만 제한된다(패스 불가).
- 소원 랭크를 갖고 있지 않거나, 갖고 있어도 지금 낼 수 있는 조합으로 만들 수 없다면(타입이 안 맞거나 이겨지지
  않음) → 아무 제한 없이 평소처럼 아무거나 내거나 패스할 수 있다.
- **폭탄은 언제나 예외**: 소원을 충족하는 수가 있어도 그냥 폭탄을 내는 것은 항상 허용된다(소원 충족 여부와
  무관하게).
  - 근거: jstanley0:tichu/play.rb#L14-27 `Play.enumerate`의 필터
    (`plays.select { play.is_a?(Bomb) || fulfills_wish?(wish_rank) }`, 단 이 필터는 "만들 수 있는 소원충족수가
    하나라도 있을 때만" 적용됨), 테스트로 확정(jstanley0:spec/play_spec.rb#L79-87 두 케이스 — "충족 가능하면
    강제(폭탄 예외)", "충족 불가능하면 자유").
  - tichu-js도 동일 결론: `isMahjongCompliant`가 "테이블 조합을 상대 손패 전체로 소원카드를 넣어 이길 수 있는지"
    먼저 확인하고, 이길 수 있을 때만 실제 선택에 소원카드 포함을 강제한다(tichu-js:src/GameLogic.ts#L378-416).
    폭탄은 최상단에서 무조건 예외 처리(L380 `if (combination.combination === BOMB) return true;`).
  - 공식 룰 요약과도 일치: "다음 플레이어가 해당 랭크 카드를 갖고 있고 **합법적으로 낼 수 있을 때만** 내야 한다"
    (officialgamerules.org).

## 5. 개(Dog)

- 오직 **리드(트릭이 비어 있을 때)**로만, 개 카드 1장 단독으로 낼 수 있다. 트릭을 따는 개념 자체가 없고,
  파워 비교 대상이 아니다.
- 개는 **트릭이 아니다** — 내는 즉시 그 자리에서 트릭이 종료(리셋)되며, 아무도(폭탄을 포함해) 그 위에 이어낼 수
  없다. jstanley0는 `make_play!`에서 `Dog` 플레이 시 곧바로 `next_trick`을 호출해 `@plays`를 비운다
  (jstanley0:tichu/state.rb#L289 `next_trick if play.is_a?(Dog)`). tichu-js도 동일하게 개를 내면 테이블을
  즉시 비우고 `combination = null` 처리한다(tichu-js:src/GameLogic.ts#L476-480).
- 개는 0점이며, 아무에게도 "귀속"되지 않는다(딸 카드가 없으므로).
- 리드는 **파트너**(자리상 2칸 건너편)에게 넘어간다(jstanley0:tichu/state.rb#L290 `offset=2`).
- **파트너가 이미 아웃(손패 0장)이면**, 리드는 그 자리부터 시계방향으로 순회하며 손패가 남은 첫 생존자에게
  넘어간다 — 이는 개 전용 특별 로직이 아니라, 매 턴 전환마다 공통으로 쓰이는 "아웃한 플레이어 건너뛰기" 로직이
  자연히 적용된 결과다(jstanley0:tichu/state.rb#L229-245 `start_turn!`의 루프).

## 6. 용(Dragon)

- 오직 **싱글로만** 낼 수 있으며, power=40으로 고정 — 어떤 일반 싱글도, 심지어 봉황도 이길 수 없다(§3.2). 용은
  1장뿐이므로 "더 높은 용"도 존재하지 않는다.
- 용이 낀 트릭을 딴 플레이어는 그 **트릭 전체(카드+점수, 용의 +25점 포함)를 반드시 상대팀 중 한 명에게
  상납**해야 한다 — 자신이 가질 수 없고, 파트너에게 줄 수도 없다. 상납 대상은 두 상대 중 승자가 직접 고른다
  (jstanley0:tichu/state.rb#L293-299 `claim_trick!`, `give_to_player_index`가 `[1,3]`(상대 두 명의 상대적
  오프셋)이어야 하며 `0`(자신)이나 `2`(파트너)는 거부됨; tichu-js:src/GameLogic.ts#L666-674, L696-728
  `giveDragon`/`dragonGiven` — "active opponent"만 선택 가능).
- **라운드가 끝나 승자가 상납 대상을 고를 기회조차 없이 종료되는 경우**(§8의 3인 아웃 종료 시점에 용 트릭이
  아직 claim되지 않은 상태) — 자동으로 **남은 유일한 상대**에게 귀속된다. 팀 구성(0·2번 vs 1·3번 좌석이 파트너)
  상, 3번째로 아웃한 사람이 속한 팀은 그 시점에 반드시 "양쪽 다 아웃"이 되므로, 남은 유일한 생존자(꼴찌)는
  항상 그 팀의 **상대편**이다 — 즉 별도 선택 UI 없이도 "상대에게만 상납"이라는 규칙이 자동으로 성립한다
  (jstanley0:tichu/state.rb#L322-327; tichu-js도 `evaluateTeamPoints`에서 동일하게 라운드 승자(1등)에게
  자동 귀속, tichu-js:src/GameLogic.ts#L166-169).

## 7. 폭탄(Bomb) 사용 규칙

- 폭탄 2종은 §2 참조. **어느 쪽에도 봉황 사용 불가**(§3.1).
- **턴이 아니어도 낼 수 있다.** 트릭이 열려 있는 동안(즉 `plays.last`가 존재하는 동안)에는 그 순간의 지정된
  차례 플레이어뿐 아니라 **네 명 전원**이 언제든 폭탄으로 끼어들 수 있다. 이는 심지어 어떤 플레이어가 이미
  트릭을 "따낸"(더 이상 아무도 응수하지 않아 승자가 확정된) 직후, 아직 공식적으로 claim하기 전 상태에서도
  동일하게 적용된다 — jstanley0의 `start_turn!`은 트릭이 열려 있는 한(리밋보 상태 포함) 현재 차례가 아닌 모든
  플레이어에게도 `Bomb.enumerate(player.hand, plays.last)`로 폭탄 합법수를 계산해 부여한다
  (jstanley0:tichu/state.rb#L247-256).
- 폭탄은 **조합 타입 매칭을 무시**하고 어떤 비-폭탄 트릭 위에도 무조건 낼 수 있다. 이미 트릭 위에 폭탄이
  놓여 있다면, 그보다 **더 강한 폭탄만**(§1.2 통합 파워 스케일로 비교) 낼 수 있다.
- **개(Dog) 위에는 낼 수 없다** — 규칙 위반이라기보다, 개는 애초에 "열린 트릭"으로 남지 않기 때문에(§5) 구조적으로
  응수 대상이 존재하지 않는다.
- (규칙이 아닌 구현 참고) 실시간 대전에서는 파트너 두 명이 거의 동시에 같은 트릭에 폭탄을 내는 경합이 생길 수
  있다. jstanley0는 "직전 3초 이내에 파트너가 이미 폭탄을 냈다면 재차 폭탄 제출을 거부"하는 네트워크 레벨
  가드를 둔다(jstanley0:tichu/state.rb#L346-350 `simulbombing_partner?`). 이는 공식 티츄 규칙이 아니라 실시간
  구현 특유의 경합 방지 장치이므로, 이 프로젝트에서 채택 여부는 별도 설계 판단이다.

## 8. 라운드 종료와 정산

### 8.1 종료 조건 (매 플레이 직후 검사)
1. **3인 아웃**: 손패를 다 낸 플레이어가 3명이 되는 순간 라운드 즉시 종료. 마지막 남은 1명이 "꼴찌".
2. **원투 피니시(더블 윈)**: 손패를 가장 먼저 다 낸 두 사람이 **파트너 사이**로 확인되는 순간(즉 아웃 순서의
   1·2번째가 정확히 한 팀), 3번째·4번째를 기다리지 않고 즉시 종료. 반대로 1·2번째 아웃이 서로 다른 팀이면 이
   조건은 성립하지 않으며(설령 이후 한 팀이 전원 아웃되더라도), 라운드는 계속되어 결국 조건 1(3인 아웃)로
   종료된다.
   - jstanley0: `out_order`가 `[0,2]/[2,0]/[1,3]/[3,1]`(정확히 앞 2자리, 파트너 쌍)일 때만 성립
     (jstanley0:tichu/state.rb#L338-344).
   - tichu-js: `mustEndGameRound`는 "팀 한쪽이 완전히 아웃"인지만 검사하는데, 이 조건은 3인 아웃 도중에도 우연히
     성립할 수 있다(예: 아웃 순서 0→1→2 진행 중 세 번째에 팀{0,2}가 완전히 아웃됨). 그러나 그 시점엔 이미 3명이
     아웃되어 `activePlayers`가 1명뿐이므로 `endGameRound`의 `activePlayers > 1` 분기가 거짓이 되어 더블윈
     보너스(200점)가 아닌 일반 3인-아웃 정산으로 빠진다(tichu-js:src/GameLogic.ts#L131-248). 즉 **두 구현은
     검사 방식은 다르지만 결과적으로 완전히 동일한 조건**(첫 두 명이 파트너일 때만 더블윈)에 도달한다.

### 8.2 더블 윈 정산
- 이긴 팀에게 **카드점수와 무관하게 고정 200점**을 부여한다. 개별 카드(5/10/K/용/봉황)의 점수는 이 라운드의
  기본 점수 계산에서 완전히 무시된다.
- 티츄/그랜드티츄 보너스(§8.4)는 이와 별개로 정상 적용된다.

### 8.3 3인 아웃 정산
1. 1·2·3번째로 아웃한 세 플레이어가 라운드 중 직접 **따낸 트릭**의 점수는 각자 자기 팀에 더한다. 단, **꼴찌
   (4번째, 유일하게 손패가 남은 플레이어)가 라운드 중 따낸 트릭의 점수는 꼴찌 자신의 팀이 아니라 1등(가장
   먼저 아웃한 플레이어)의 팀에게 돌아간다.**
2. **꼴찌의 아직 못 낸 손패**는 카드점수로 환산해 **상대팀**(꼴찌 자신의 팀이 아닌 쪽)에게 전부 넘어간다.
3. 카드점수는 §1.1대로(5=5, 10/K=10, 용=+25, 봉황=-25, 전체 합=100) — 정상 종료된 한 라운드의 두 팀 카드점수
   합계는 항상 100이 되어야 한다(구현 검증용 불변식; jstanley0는 이를 실제로 assert한다,
   jstanley0:tichu/state.rb#L435-436 `raise "apparently I can't count" unless new_total == old_total + 100`).
4. 3번째 플레이어가 아웃하는 마지막 플레이로 만들어진 트릭이 아직 claim되지 않았다면: 그 트릭에 **용이 없으면**
   3번째 아웃자 본인에게, **용이 있으면** §6대로 남은 유일한 생존자(꼴찌, 항상 상대팀)에게 자동 귀속된다.
   단, 그 마지막 플레이가 **개(Dog)**였다면 애초에 딸 트릭이 없으므로(§5) 아무것도 귀속시키지 않는다
   (jstanley0:tichu/state.rb#L319-330 `next_turn!`).

### 8.4 티츄 / 그랜드 티츄 보너스
- 각각 ±100 / ±200점. **성공 여부는 오직 "그 라운드에서 실제로 가장 먼저 손패를 다 냈는가"(1등, 즉 아웃 순서
  1번째)로만 판정**되며, 더블윈이든 3인아웃이든 라운드의 다른 결과와 무관하게 개별적으로 채점된다.
  - 1등으로 아웃했다면 → 자기 팀에 +100(티츄) 또는 +200(그랜드티츄).
  - 콜은 했지만 1등이 아니었다면 → 자기 팀에 -100 또는 -200.
  - 콜하지 않은 플레이어는 이 항목에 기여分 없음.
  - 근거: jstanley0:tichu/state.rb#L440-444 `score_tichus!`,
    `scores[index%2] += player.tichu * ((index==out_order[0]) ? 1 : -1)`.

### 8.5 게임 종료
- 목표 점수(기본 1000점) 누적. 매 라운드 정산 직후, 어느 한쪽 팀의 누적 점수가 목표 이상이고 **두 팀 점수가
  서로 다르면** 그 시점에 게임 종료, 높은 쪽 승리.
- 두 팀 다 목표를 넘겼더라도(또는 종료 조건은 충족했더라도) **점수가 동점이면 게임은 끝나지 않고 라운드를
  한 번 더 진행**한다(jstanley0:tichu/state.rb#L388-393).

## 9. 참고 구현이 처리한 까다로운 엣지케이스 (출처 포함)

1. **봉황은 용을 이길 수 없다** — 일반 공식(P+1)이 아니라 명시적 예외.
   (jstanley0:tichu/play.rb#L121; tichu-js:src/GameLogic.ts#L332-336)
2. **A 위는 용/폭탄만 이긴다** — 별도 규칙이 아니라 "A(28) + 봉황(+1=29)"가 실물로 만들 수 있는 최댓값이라는
   사실의 자연스러운 귀결. (jstanley0:spec/play_spec.rb#L22-23으로 테스트 확정)
3. **풀하우스 "페어+페어+봉황"은 반드시 높은 쪽이 트리플** — jstanley0는 낮은 쪽 조합을 아예 합법수에서
   제거, tichu-js는 플레이어가 자유 선택 가능(설계 차이, 본 프로젝트는 jstanley0 방식 채택).
   (jstanley0:tichu/play.rb#L244-246, spec/play_spec.rb#L59; tichu-js:src/CardCombinations.ts#L475-503)
4. **스트레이트의 봉황은 항상 top을 최대화하는 위치에만 놓인다**(A 천장에 막힐 때만 하단 채움 허용) — jstanley0는
   강제, tichu-js는 자유 선택(본 프로젝트는 jstanley0 방식 채택). (jstanley0:tichu/play.rb#L192,
   spec/play_spec.rb#L45-46; tichu-js:src/CardCombinations.ts#L430-449)
5. **연속 페어(사다리)의 봉황 배치는 스트레이트와 달리 상단-우선 강제가 코드에 없다** — jstanley0의
   `Ladder.enumerate`에는 Straight와 동등한 dedup 필터가 존재하지 않으며, tichu-js도 자유 선택을 허용한다. 두
   구현 모두 이 지점을 강제하지 않으므로 **미확정 지점**으로 남겨두고, 일관성을 위해 스트레이트와 동일한
   "top 우선" 규칙을 권장안으로 제안하되 확정 사양은 아님을 명시한다. (jstanley0:tichu/play.rb#L204-229 대조;
   tichu-js:src/CardCombinations.ts#L257-366)
6. **같은 수트로만 된 5장 이상 연속은 일반 스트레이트가 아니라 무조건 폭탄(스트레이트 플러시)** — 일반
   스트레이트 열거 시 단일 수트 조합을 명시적으로 제외한다. (jstanley0:tichu/play.rb#L191)
7. **마작은 싱글로는 항상 리드 전용** — rank=1(power=2)이 어떤 다른 싱글보다도 낮아, 이미 깔린 카드를 이길 수
   있는 경우가 구조적으로 없다. (jstanley0:tichu/card.rb rank 상수 설계, spec/play_spec.rb#L19에서 마작 포함
   패의 싱글 개수 확인)
8. **소원 의무는 "보유 + 지금 이길 수 있을 때"만 발동**, 폭탄은 항상 예외 — 보유하고 있어도 타입이 안 맞거나
   이길 수 없으면 자유. (jstanley0:tichu/play.rb#L14-27, spec/play_spec.rb#L79-87; tichu-js:
   src/GameLogic.ts#L378-416; officialgamerules.org "lawfully play it")
